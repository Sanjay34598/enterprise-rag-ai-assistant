# Contributor Guidelines

We welcome contributions from the developer community! Follow these steps to submit your changes.

---

## Branch Naming Conventions
- `feature/<short-description>`: New functional features.
- `fix/<short-description>`: Bug fixes.
- `docs/<short-description>`: Documentation changes.
- `refactor/<short-description>`: Architectural improvement without behavior change.

---

## Pull Request Submission Workflow
1. Fork the repository and create your feature branch from `main`.
2. Ensure all unit and integration tests pass locally.
3. Verify zero lint errors (`ruff check` for Python, `eslint` for TypeScript).
4. Fill out the [Pull Request Template](.github/PULL_REQUEST_TEMPLATE.md).
5. Submit the PR for code review.
